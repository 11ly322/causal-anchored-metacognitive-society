# 04 — Limits: T2, pure text cannot certify grounding

> T2 是负结果：在“无可信锚点”的纯文本通道上，任何验证器都不能同时保证 grounding 的 soundness 与 completeness。  
> 这不是说文本无用；它说文本不能**认证**外部真值。签名/哈希/溯源树只能证明“谁在什么内容上签了字/内容未被改”，不能证明“内容为真”。

## 1. 定义

### 1.1 世界、文本、grounding

- `Ω`：世界集合；`s∈Ω`。
- `C`：claim 集合；`c∈C`。
- `g: Ω×C→{0,1}`：grounding 真值谓词；`g(s,c)=1` 表示 `c` 在世界 `s` 为真。
- `T`：纯文本通道取值空间；`τ: Ω→T` 是文本生成过程。
- `V: T×C→{accept,reject}`：只读文本的验证器。
- `A`：审计器；`A` 只读 `q=(t,c)`，不读 `s`、不读非文本回执。

**GroundSound(V)**：`∀s,c: V(t,c)=accept ⇒ g(s,c)=1`。  
**Complete(V)**：`∀s,c: g(s,c)=1 ⇒ V(t,c)=accept`（或至少以高概率接受；本文件用确定性版本）。

### 1.2 “纯文本”的精确定义

纯文本通道满足：

1. `t` 是有限/可数串；
2. 验证器没有除 `t` 之外的 trusted anchor（没有共享密钥、没有可信硬件、没有独立传感器、没有第三方见证）；
3. 对手 A0 可以生成任意 `t`（可计算意义下），并可选择 claim `c`；
4. 对手不能计算哈希的第二原像（若 `t` 含哈希，哈希只绑定内容，不绑定真值）。

关键：**签名也是文本**。若 `t` 含公钥签名，它仍满足 1–3；它只证明“某密钥持有者签了这段文本”，不证明“这段文本为真”。若签名密钥由可信硬件/可信第三方持有且只在真值时签名，那么该硬件/第三方就是 trusted anchor（回执通道），不属于“纯文本”。

## 2. T2 — 不可区分性定理

### 定理 T2（纯文本 grounding 不可能）

**假设**：
1. 先验 `s=0,1` 等概率；`c` 固定；`g(0,c)=0`, `g(1,c)=1`。
2. 文本分布满足 `P(t|s=0)=P(t|s=1)` 对所有 `t`（对手可把任一世界的文本改写成另一世界的文本；或文本与 `s` 独立）。
3. `V` 只读 `(t,c)`，没有 trusted anchor。

**结论**：对任意 `V`，
```text
Pr_{s,t}[V(t,c)=accept ∧ g(s,c)=0] + Pr[V(t,c)=reject ∧ g(s,c)=1] ≥ 1/2
```
即“错误接受 + 错误拒绝”的总错误率至少 1/2；不存在同时 GroundSound 且 Complete 的 `V`。

**证明**：
- 由假设 2，`(t,c)` 的分布在 `s=0` 与 `s=1` 下相同；`V` 的输出分布也相同。
- 令 `a = Pr[V(t,c)=accept]`（与 `s` 无关）。
- 在 `s=0`（真值为 0）上，错误接受率 = `a`；在 `s=1`（真值为 1）上，错误拒绝率 = `1-a`。
- 总错误率 = `(1/2)a + (1/2)(1-a) = 1/2`。∎

**状态**：PROVEN（在假设 2 下；这是信息论下界，不是 CAMS 特有的）。

**So what**：
- 任何“纯文本自证”的审计器，若接受，就能被同样的文本骗；若拒绝一切，则没有 completeness。它不能区分“真回执”与“对手写的同样文本”。
- 哈希/签名/溯源树不能突破 T2；它们至多把“文本内容”绑定到“密钥/内容”，不能把文本绑定到世界真值。要突破，必须引入 trusted anchor（非文本回执、可信硬件/第三方、完整性审计）。

**反例（证明失败的情形）**：若 `t` 包含由可信传感器在测量时签名的读数，且验证器持有传感器公钥并检查 freshness，那么 `t` 实际上携带了 `R`；假设 2 失败，T2 不适用。此时 grounding 可能成立——这正是 T1′ 的“回执通道”，不是纯文本。

## 3. 三个常见反驳与回应

### 3.1 “哈希/区块链不可篡改”

- 哈希只保证“内容未被改”，不保证“内容最初为真”。对手可以在世界 0 写“世界 1”的文本并计算正确哈希。
- 区块链/时间戳只证明“某文本在某时刻存在”，不证明“文本描述世界”。
- 若链上数据由可信 oracle 写入，那个 oracle 是 trusted anchor；T2 的假设 3 失败。

### 3.2 “签名/公钥基础设施”

- 签名证明“私钥持有者签了文本”；若私钥持有者可以签假话，签名不提供 grounding。
- 若私钥只在真值时使用，签名者是一个可信 oracle；这是 `R`，不是纯文本。
- 重放：旧签名可附到新 claim；需要 `session/claim_hash/nonce` 绑定；绑定仍是回执通道问题（02 §5.1）。

### 3.3 “多模型投票/自我一致性”

- 多个文本生成器仍只产生文本；若它们共享同一偏差/对手可同时欺骗，T2 的不可区分性仍在。
- 投票改变的是 `V` 的函数，不改变 `P(t|s=0)=P(t|s=1)` 的信息论事实；除非投票者中有可信回执源。
- “多 agent 投票”不是 grounding 的证明；它只是另一个文本聚合器。

## 4. T2′ — Coverage 不能证明世界覆盖

### 定理 T2′（选择性报告下 coverage 不忠实）

**假设**：
1. 任务规范 `Req` 不是审计器可观察的；审计器只看到提交的 `q`。
2. 两个任务 `q0,q1` 有相同的提交证据/claim，但 `Req(q0)≠Req(q1)`；在 `q0` 中未提交的证据反驳 `c`，在 `q1` 中不存在这些证据。
3. 审计器用 `cov(q)=|已验证提交|/|Req(q)|`；但它不知道 `Req`，只能用提交集合的 `Req_hat`。

**结论**：存在两个世界/任务使 `q` 相同但 grounding 真值不同；任何只读 `q` 的 `V` 不能同时正确判定二者。coverage 高，不蕴含世界覆盖高。

**证明**：构造 `q` 相同、`Req` 不同；`V` 的输入相同，输出必须相同；但两个任务的真值不同，故至少一个错误。∎

**状态**：PROVEN（构造性；依赖“Req 不可观察/无完整性审计”）。

**So what**：审计层只能报告“我提交的证据覆盖”，不能报告“世界上所有相关证据覆盖”。要后者，需要完整性假设/第三方见证/遗漏审计；否则 coverage 可被 A3 选择性报告利用。

**反例（证明失败的情形）**：若存在一个可信的“应提交证据清单”（第三方审计/预注册任务规范），且该清单本身不可被 Prover 改写，则 `Req` 可观察，T2′ 不适用；此时 coverage 可以忠实于该清单。

## 5. 边界：T2 不声称什么

- 不声称“文本没有信息”：文本可以传递大量信息，只是不能单独认证外部真值。
- 不声称“所有审计都不可能”：有可信回执/硬件/第三方时可能；T2 的条件是“无可信锚点”。
- 不声称“签名无用”：签名对来源/完整性/责任有用；它只是不提供 grounding。
- 不声称“CAMS 已解决 grounding”：v5.0 只承诺 provenance soundness；T2 说明它不能承诺更多。

## 6. 红队路径（文本不可能）

> 如果 CAMS 的输入最终只有文本（例如模型自报“我调用了工具”），那么 T2 直接适用：审计层只是把文本重新排版成 contract；它不能证明工具真的被调用。  
> 若 CAMS 的输入含真实工具回执，但回执没有 freshness/claim binding，A1 重放仍可欺骗；T1′ 的成功依赖绑定，不是“有回执”四个字。  
> 若回执由 Prover 自己生成（模型伪造 JSON），它仍是文本；T2 适用。H4 的 `non_text` 标志必须由可信执行环境/工具侧写入，不能由模型自报——否则 `non_text=1` 只是另一个文本字段。
