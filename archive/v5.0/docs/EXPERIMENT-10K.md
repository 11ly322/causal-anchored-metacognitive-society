# EXPERIMENT-10K — 10³ kill-test 协议（2–4 周，单人可跑）

> 修订说明：这是 v5.0 的 **协议级 kill test**，不是 0.1B 模型性能测试，也不是 10⁴/10⁵ 主实验。它只回答一个问题：CAMS/CFP 的结构差异是否值得进入 10⁴。**当前没有运行数据。** 所有阈值是 `[设计]`，预算是 `[假设]`，未知量写 `[TBD]`。

## 0. 一页协议（A4 可复现）

- **规模**：1,000 个代理；20 轮；5 个基线；3 个固定种子（7/17/27）。
- **任务**：12 通道合成政治管理沙箱 `TB-12`；2 条隐藏关系；3 个上下文；每个 run 固定 50 次局部干预。
- **x_ns**：只接受工具执行回执（receipt），不接受自然语言日志；见 §2。
- **主对比**：完整 CFP vs `A-skeleton`；主指标 `T_π`（协方差门控层间传递事件数）。
- **停止**：3 个种子跑完后，单侧置换检验 `p≥0.05` 即停，判“未通过 kill test”；`p<0.05` 但效应量 < 预注册最小值也停。
- **预算**：[假设] 15 个 run × 0.5 CPU-hour ≈ 7.5 CPU-hour；本机 ¥0–1 电费；云上 `[TBD]`；人力 10 人日。
- **产出**：15 个 `trace.jsonl` + 1 个 `metrics.json` + 1 页结论；不产出“智能体社会”演示。

## 1. 研究问题与假设

**Q1**：在同等参数/交互预算下，完整 CFP 是否比去掉 H1–H4 的 `A-skeleton` 产生更多“协方差门控驱动的层间传递事件”（`T_π`）？
**Q2**：`T_π` 的差异是否伴随 `D_π`、确定率、溯源匹配、`z_sep` 的同向变化，而不是只改一个计数？
**Q3**：`x_ns` 被切断、`⊥` 被改成离散端口、模式分离被去掉时，上述差异是否消失？

- **H1 [假设]**：`T_π(full) > T_π(A-skeleton)`，且 `D_π(full) ≥ D_π(A-skeleton)`。
- **H0**：两者无差异，或差异只出现在单一指标上。
- **失败即停止**：若 H0 不被拒绝，10⁴ 不启动；不能把 100B 当补救。

## 2. 任务集与数据来源

### 2.1 `TB-12` 沙箱

- 变量：4 个杠杆（transfer/audit/penalty/transparency）、3 个上下文（scarcity/monitoring/mobility）、5 个结果（resource/compliance/conceal/exit_rate/legitimacy）。
- 关系：10 条公开关系 + 2 条隐藏关系；隐藏关系不暴露给代理，只用于生成结果。
- 轮次：20 轮；每轮每个代理可读取当前上下文、执行一个工具动作、收到一条 receipt。
- 数据来源：**合成数据**，由固定种子生成；不使用真实个人数据、不使用真实政治事件标签。`[设计]`
- 外部效度：这是协议测试，不是政治预测；不得从结果外推真实政策效果。

### 2.2 `x_ns` 的操作化：tool execution receipt

`x_ns` 不是文本，不是“模型说自己做了”，而是工具执行后生成的回执：

```json
{
  "receipt_id": "r-000123",
  "tool_id": "budget_transfer",
  "timestamp": 1730000000.123,
  "exit_code": 0,
  "stdout_hash": "sha256:...",
  "latency_ms": 42,
  "resource_delta": {"cpu_ms": 40, "memory_mb": 12},
  "input_digest": "sha256:...",
  "output_digest": "sha256:..."
}
```

- **非符号叶**：`tool_id`、`exit_code`、`latency_ms`、`resource_delta`、`output_digest` 至少一项进入 L1 的非文本通道；不允许只把 `stdout` 转成文本 token。
- **可伪造性**：receipt 由执行器签名/哈希；代理不能自己写 `exit_code=0`。
- **切断条件**：`CUT-NS` 只关闭 receipt 通道，保留文本通道；用于 F8a。
- **测量失败**：`exit_code≠0` 或 `latency_ms` 超阈值时，该样本进入 `MEASUREMENT_FAILURE`，不得当成 `NO_RISK`。

### 2.3 数据划分

- 训练/校准/测试按 run 划分；测试轮次的 receipt 在预测时不可见。
- 隐藏关系只在测试时用于评分，不进入代理输入。
- 3 个种子生成 3 套独立沙箱；不得用测试种子调阈值。

## 3. 五个基线

| 基线 | 构造 | 预算对齐 | 目的 |
|---|---|---|---|
| **A-skeleton** | 保留三层骨架，去掉 H1–H4；无指纹、无始终 Σ、无精度回灌、无非符号叶 | 同参数、同 20 轮、同 50 次干预 | 主对照：结构是否承重 |
| **A-noNS** | 完整 CFP，但关闭 receipt 通道，只保留文本 | 同上 | 检验符号接地 |
| **A-discrete** | 把 `Σ>τ_cov` 改成二值弃权端口，高协方差直接短路 | 同上 | 检验“始终产生协方差” |
| **dense-0.1B** | 同参数预算的稠密路由代理；无分区、无局部稀疏、无侧抑制 | 同上 | 检验分区/稀疏是否必要 |
| **B** | 同预算集中式序列模型；无分层、无契约 | 同上 | 检验“单体同预算等价” |

- 10³ 阶段 `dense-0.1B` 是 **代理实现**（线性/表格策略，非真实 0.1B 网络）；它只测试“稠密 vs 分区”的结构差异。真实 0.1B 放到 G2，不在此阶段冒充。`[设计]`
- 可选补充：`B_rule`（手工规则）、`B_oracle`（真实证据上界）；它们不替代上述五个基线。

## 4. 指标定义与公式

| 指标 | 定义 | 用途 |
|---|---|---|
| `T_π` | 一个“层间传递事件”：某层 `Σ>τ_cov`，且该层的精度权重被用于下一层更新；按事件计数 | 主指标；F8c |
| `D_π` | `1 - Jaccard(PBT_full, PBT_perm)`；`PBT` 是 trace 中 `(layer, source_hash, target_hash)` 的集合；`PBT_perm` 是 8 次证据置换后的集合 | 结构依赖；F5′/F7′ |
| `d` | 确定输出率：`determined / total`；`determined` 要求溯源树完整且覆盖率 ≥ `τ_z` | 弱证据行为；F2′ |
| `PM` | 溯源匹配率：输出叶与 receipt/文本证据的哈希匹配数 / 总叶数 | F1′；F8a |
| `z_sep` | 不同溯源 `z` 两两的 `1-cos` 均值（归一化到 `[0,1]`） | 模式分离；F11′ |
| `contract_probe_acc` | 外部脚本只读 `contract` 对 `NO_RISK/INSUFFICIENT_EVIDENCE/MEASUREMENT_FAILURE` 三态的正确率 | F10′ |
| `ROI_struct` | `revision_events / GPU-hour`（10³ 代理用 CPU-hour 折算） | F9′ |
| `FIR` | `false_insight / determined`；`false_insight` 是“确定但测试标签为错”的输出 | F3′ |

- 所有比例指标报告分子/分母；分母 <30 时记 `[TBD]`，不得写“显著”。
- 主指标 `T_π` 用单侧置换检验（10,000 次）；效应量用 `(T_π_full - T_π_skel)/T_π_skel`，最小效应 `[TBD]` 由 10³ 预实验后冻结。
- 多重比较：F1′–F8′ 分别预注册；探索性指标用 Holm/FDR，不得事后挑显著。

## 5. 运行流程

1. **预注册**：冻结阈值、种子、基线、主指标、停止规则；写入 `prereg.json`。
2. **Pilot**：1 个种子、1 个基线，检查事件数是否 ≥30；不足则扩大轮次或降低 `τ_cov`，但只能改一次并记录。
3. **主跑**：5 基线 × 3 种子 = 15 runs；每个 run 20 轮、50 次局部干预。
4. **盲评**：评分脚本不知道基线标签；先算指标，后解盲。
5. **停止判断**：3 种子合并后看 `T_π` 单侧 p 值；`p≥0.05` 立即停，不追加种子“救结果”。
6. **复算**：发布 `trace.jsonl`、`prereg.json`、`metrics.json`、`analysis.md`；任何人可复算。

## 6. 算力 / 人力预算

> 以下均为 `[假设]`，不是报价；真实价格需在采购时填 `[TBD]`。

- **代理实现**：1,000 agents × 20 rounds × 15 runs ≈ 300k agent-round；按单核 0.5 CPU-hour/run，约 **7.5 CPU-hour**；8 核机器 wall-clock 约 1–2 小时。
- **GPU**：10³ 代理不需要 GPU；若用 GPU 加速，`[假设]` 0.2 GPU-hour/run × 15 = **3 GPU-hour**，租用价 `[TBD]` 元/GPU-hour。
- **电力**：`[假设]` 整机 120W × 8 小时 ≈ 0.96 kWh；按 `[假设]` 0.6 元/kWh ≈ **0.6 元**（本机）；云费用另计 `[TBD]`。
- **人力**：1 人 × 10 人日（2 周）；若按 `[假设]` 1,000 元/人日，机会成本 ≈ **10,000 元**；学生/自研可记 0 现金。
- **总现金**：本机 ≈ **0–100 元**（电费/存储）；云上 `[TBD]`，必须在采购前填实际单价。
- **明确排除**：真实 0.1B 模型推理、10⁴/10⁵、人工标注、注册制试点；这些不在 10³ 预算内。

## 7. 预期失败模式

1. **A-skeleton 追平**：`T_π` 无差异 → 结构不承重，停止，不扩 10⁴。
2. **只有计数差异**：`T_π` 显著但 `D_π/PM/z_sep` 无同向变化 → 可能是实现假象，停止。
3. **事件不足**：每格 <30 次事件 → `[TBD]`，先扩大轮次，不得宣称通过。
4. **离散弃权更好**：`A-discrete` 在弱证据下更稳 → “始终 Σ”不成立，回到设计。
5. **预算不可比**：基线不同参数/不同干预数 → F1′ 四段式失败，结果作废。
6. **泄漏**：测试 receipt/隐藏关系进入输入 → F4′ 失败，结果作废。
7. **代理与 0.1B 脱节**：10³ 只证明协议，不证明 0.1B；这是边界，不是失败，但不能据此宣称模型能力。

## 8. 10³ 通过后做什么

- 只有 `T_π` p<0.05、效应量 ≥ 预注册最小值、且 F8a/F8b 至少两项同向，才进入 10⁴ 设计。
- 10⁴ 的样本量、GPU 预算、τ 校准方案必须重新预注册；不得直接把 10³ 的 p 值当 10⁴ 结论。
- 10³ 不通过时，允许改一次机制并重跑；第二次仍失败则停止该路线，不用 100B 规模补救。
