# CAMS 审计层：通俗解释

> 这页解释代码在做什么，不解释“智能”“理解”或政治。

## 一句话

给 Agent 的答案配一张“证据收据”：每句话靠哪些工具回执、回执有没有被改、覆盖够不够、范围对不对；不够就返回一个结构化的“拒绝单”，而不是一个看起来很确定的答案。

## 三个角色

- **回执**：shell 输出、数据库行、网页抓取、传感器读数。带校验和。
- **溯源树**：每句话声明“我靠哪几张回执”；树只核对存在、校验和、范围、关系，不判断语义真假。
- **门控**：全部核对通过 + 覆盖率 ≥80% + 协方差 ≤0.60 → 接受；否则拒绝。

## 拒绝单长什么样

```json
{
  "contract_version": "1.0",
  "reason_code": "MEASUREMENT_FAILURE",
  "evidence_coverage": 0.0,
  "provenance_summary": "sha256:...",
  "escalation_path": "human_review",
  "adapter_cost": 0.0
}
```

外部程序只用这个对象就能分清：没风险、证据不足、测量失败、越界。需要读内部协方差才能分清，就说明契约没做好。

## 它不做什么

- 不训练模型；
- 不模拟政治；
- 不声称“理解”；
- 不把 0.1B/100B 当理由；
- 不解决语义蕴含：有效回执仍可能支持错误结论，这是公开的漏洞。

## 怎么跑

```bash
python examples/demo_code_agent.py --offline
python bench/run.py --split test
```

合成基准数字只说明代码在构造任务上的行为，不是 live 实验，也不是“理解”的证据。
